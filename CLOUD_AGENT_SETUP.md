## 🔧 Activation Instructions (One-Time Setup)

### Step 1: Configure GitHub Secrets

Go to: **GitHub → Settings → Secrets and variables → Actions**

Add the following secrets:

```
GH_OWNER = matiasportugau-ui
GH_SCAN_TOKEN = <your-github-token>
```

#### How to Create `GH_SCAN_TOKEN`:

**Option A: Fine-grained Personal Access Token (Recommended)**
1. Go to: https://github.com/settings/tokens?type=beta
2. Click "Generate new token"
3. Set:
   - Name: `Cloud Agent Read-Only Token`
   - Expiration: `90 days` (or custom)
   - Repository access: `All repositories` (or select specific ones)
   - Permissions:
     - **Contents**: `Read-only` ✅
     - **Metadata**: `Read-only` (automatic)
4. Generate token and copy it
5. Add as `GH_SCAN_TOKEN` secret

**Option B: Classic Token (Legacy)**
1. Go to: https://github.com/settings/tokens
2. Generate new token (classic)
3. Scopes: `repo` (read-only access)
4. Copy token and add as `GH_SCAN_TOKEN` secret

⚠️ **Security**: This token only needs READ access. Never use tokens with write permissions.

### Step 2: Manual Test Run

1. Go to: **Actions → cloud-agent-daily**
2. Click "Run workflow" button
3. Wait 2-5 minutes for completion

## ⚙️ Configuration

### Adjust Performance (if workflow is slow or hits rate limits)

Edit `.github/workflows/cloud-agent-daily.yml`:

```yaml
env:
  BRANCH_LIMIT: "50"        # Limit branches per repo (0 = unlimited)
  BRANCH_ALLOW_REGEX: "^(main|master|develop|dev|staging|production|release/|hotfix/)"
```

**Recommendations:**
- **Small org (<10 repos)**: `BRANCH_LIMIT: 0` (all branches)
- **Medium org (10-50 repos)**: `BRANCH_LIMIT: 50`
- **Large org (>50 repos)**: `BRANCH_LIMIT: 20` + strict regex

### Adjust Scoring Weights

Edit `config/weights.yml`:

```yaml
demanda: 0.35              # Demand weight
margen_potencial: 0.25     # Profit margin weight
fit_bmc: 0.15              # Business model fit
facilidad_logistica: 0.15  # Logistics ease
ventaja_competitiva: 0.10  # Competitive advantage
```

Weights must sum to 1.0.

### Change Schedule

Edit `.github/workflows/cloud-agent-daily.yml`:

```yaml
on:
  schedule:
    - cron: "15 11 * * *"  # 11:15 UTC daily (change as needed)
```

### Filter Repositories

To scan only specific repos, edit workflow:

```yaml
env:
  REPO_FILTER: "chatbot"   # Only scan repos with "chatbot" in name
  # Or: REPO_FILTER: ""    # Scan ALL repos (default)
```

## 🚦 Risk Assessment (Traffic Light System)

### 🟢 Green (Low Risk)
- ✅ Keys-only extraction (no secret values)
- ✅ Artifacts published to Actions (not committed to code)
- ✅ Read-only token required

### 🟡 Yellow (Medium Risk)
- ⚠️ All repos + all branches can hit GitHub rate limits
- ⚠️ Long execution time for large organizations
- **Mitigation**: Adjust `BRANCH_LIMIT` and `BRANCH_ALLOW_REGEX`

### 🔴 Red (High Risk)
- 🛑 Token with excessive permissions (write/admin)
- 🛑 Token exposure in logs
- **Mitigation**: Use read-only token, rotate if exposed

## 🐛 Troubleshooting

### Workflow fails with "Missing GH_SCAN_TOKEN or GH_OWNER"
- **Solution**: Add secrets in GitHub Settings → Secrets and variables → Actions

### Workflow times out or is very slow
- **Solution**: Reduce `BRANCH_LIMIT` or tighten `BRANCH_ALLOW_REGEX`
- Example: `BRANCH_LIMIT: "10"` and regex: `"^(main|master)$"`

### Rate limit errors (403)
- **Solution**: Workflow hit GitHub API rate limits
- Wait 1 hour for reset
- Consider reducing scope (fewer branches/repos)

### No env files found
- **Normal**: Some repos may not have .env files
- Check artifact `env_inventory.json` to see what was scanned

### Issue not created
- **Solution**: Workflow needs `issues: write` permission (already configured)
- Check workflow logs for error message
